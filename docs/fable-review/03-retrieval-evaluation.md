## Held-out retrieval eval (independent method, not the build's queries)

Method: sample real `ken_said`/`relayed` memories; have gpt-oss:120b (which
never sees the store) write a natural question whose answer IS that memory;
measure whether the source memory appears in top-k. Target chosen independently
of the ranker → a hit is earned. seed=1729, N=12, run this session with the
backfill stopped and **the F2 ANN bug still present**.

    hit@1 = 67%   hit@5 = 92%   hit@10 = 92%   MRR = 0.732

The one miss (m697) was a genuinely vague query ("What kind of scheduled tasks
does Ken prefer?") with no distinctive term. This is a good result — and a
CONSERVATIVE one, because the semantic leg is running at 28% recall (F2). That
92% hit@5 is being carried by keyword + graph, which is simultaneously:
  - strong evidence FOR the hybrid design (redundancy masked a broken leg), and
  - the reason F2 stayed invisible to the build (the legs that work covered it).

Caveat: questions were generated by a model from the memory text, so they share
vocabulary with the target — this flatters the keyword leg vs. how a human would
phrase a cold query. Real-world hit@5 is probably lower than 92%. A human-written
query set is the right next step (handoff).
