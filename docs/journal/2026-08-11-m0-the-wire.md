M0's charter: prove the `MemoryProvider` plumbing end to end with the dumbest
possible brain. No extraction, no ranking, no consolidation — just: a turn
goes in, *something* relevant-shaped comes back out in the next session.

## What went in

The real provider contract turned out to be richer than the handoff's sketch
— reading the actual ABC (not its documentation summary) surfaced three
things the shim had to honor: recall returns a plain formatted string, not
structured data; a separate `queue_prefetch` hook exists precisely so
`prefetch` can be a cache read (the "must return fast" contract has
first-class support); and `sync_turn` receives the full OpenAI-style message
list, tool calls included. That last one matters beyond M0: the future
causal-attribution judge needs the verbatim record of what the agent actually
did, and the predecessor system had to reconstruct that from run logs because
its database column truncated at 500 characters. Our episodic schema keeps
the full message list from the first row.

Shipped today:

- **Service** (FastAPI + asyncpg) at its reserved DMZ address: `POST
  /v1/turns` (episodic ingest), `GET /v1/prefetch` (M0 recall: most recent
  exchanges from *other* sessions — what a fresh session can't already
  know), `POST /v1/sessions/{id}/end` (boundary marker; becomes the
  consolidation enqueue in M2), `/health`.
- **Schema 0001**: sessions + episodic turns with full-message JSONB, a
  generated FTS column (the keyword leg of M1's hybrid retrieval, ready
  early), and a partial index on unconsolidated rows (the dream pass's
  entry point, ready early).
- **Provider shim**: one stdlib-only file implementing the ABC as a thin
  HTTP client. Threaded write queue that drops rather than blocks; recall
  served from a cache a background thread refreshes; non-primary agent
  contexts (cron, subagents) skip writes so scheduled jobs can't pollute
  the episodic record. The agent must never wait on its memory.

## What the wire test showed

From a DMZ vantage: ingest a turn in session A, prefetch from session B, get
session A's exchange back formatted for injection. From the LAN vantage (the
same router path the workstation uses): health and recall both answer. The
seam works in both directions that matter.

Not yet done: the provider directory copied into the live agent's plugin
directory and activated — that's a two-step manual install on the
workstation, plus one config line. The demo of record (a real agent turn
captured, a real injection observed) happens there.

## Friction log, same-day

Three small potholes, none novel: a packaging config that double-included the
migrations directory (build-time error, clear message); a generator
expression that needed parentheses (the service failed at import, caught on
first container start); and the shared Postgres refusing `CREATE DATABASE ...
OWNER role` until the admin user was granted the role first — that one is a
managed-Postgres convention worth a gotcha, since it will recur for every
future tenant database.
